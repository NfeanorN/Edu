Vue vs Angular — Interview Prep

Шпаргалка под собес: отличия, подробные особенности Vue 3 и ответы. Для тех, у кого база Angular.

Главные отличия

Angular Vue
Философия Полноценный фреймворк (opinionated) Библиотека + экосистема (гибче)
Язык Почти всегда TypeScript JS или TS (на выбор)
Структура .ts + .html + .scss + декораторы SFC .vue = template + script + style
Реактивность Zone.js / signals Proxy: ref / reactive (Vue 3)
DI Встроенный DI-контейнер Нет классического DI → provide/inject, composables
Роутинг / store Router + NgRx / Signals vue-router + Pinia
Сборка Angular CLI / esbuild Часто Vite
Формы Reactive Forms / signal forms — мощно для enterprise v-model проще; сложные формы — вручную / библиотеки

Особенности Vue 3 (подробно)

Учи это в первую очередь. Всё про Vue 2 / Vuex / filters — на вкладке Старое.

1. Реактивность на Proxy

Vue 3 оборачивает данные в Proxy. Когда ты читаешь свойство в template / computed / watch — Vue запоминает зависимость. Когда меняешь — планирует обновление DOM.

  • ref(x) — обёртка для любого значения. В script: count.value, в template: просто count (авто-unwrap).
  • reactive(obj) — глубокая реактивность объекта. Удобно для форм/стейта, но при деструктуризации теряется реактивность → toRefs.
  • shallowRef / shallowReactive — реактивность только на верхнем уровне (большие объекты, сторонние либы).
  • markRaw — «не делай реактивным» (классы, chart instances).
  • readonly — read-only обёртка (пропсы наружу без мутаций).
Angular: Zone.js / signals патчат «когда проверить». Vue: ты явно помечаешь реактивные данные, трекинг точечный.

2. Composition API и <script setup>

Логику группируют по фичам, а не по options-секциям. Composable = функция useXxx(), которая возвращает state + methods (аналог «сервис + хуки»).

  • <script setup> — сахар: top-level bindings автоматически доступны в template.
  • defineProps / defineEmits / defineModel (Vue 3.4+) — без export default.
  • Легко шарить логику между компонентами без mixins.
  • Лучше tree-shaking и TypeScript, чем Options API.
Если знаешь Angular-сервисы и React hooks — Composition API ляжет быстро.

3. SFC (.vue) и стили

  • Один файл: template + script + style.
  • <style scoped> — стили только этого компонента (data-атрибут).
  • CSS modules: <style module>.
  • Можно SCSS: lang="scss".
  • Slots: <slot>, named slots, scoped slots — как ng-content / content projection, но гибче.

4. Template и директивы

  • v-bind:attr / :attr — привязка атрибута.
  • v-on:click / @click — события.
  • v-model — двусторонний биндинг (input, select, custom components).
  • v-if / v-else-if / v-else — условный рендер (убирает из DOM).
  • v-show — только CSS display.
  • v-for — всегда с :key.
  • v-html — сырой HTML (осторожно с XSS).
  • v-once, v-memo — оптимизации рендера.

5. computed / watch / watchEffect

  • computed — кэшируемое производное значение. Пересчёт только если изменились зависимости.
  • watch(source, cb) — явный источник; можно deep, immediate, flush.
  • watchEffect(fn) — сам собирает зависимости при первом запуске; сразу выполняется.
Правило: данные для UI → computed. Side effects (API, localStorage) → watch / watchEffect.

6. Lifecycle (Composition)

  • onBeforeMount / onMounted — до/после монтирования в DOM
  • onBeforeUpdate / onUpdated
  • onBeforeUnmount / onUnmounted — чистка таймеров, подписок
  • onErrorCaptured — ошибки в дочерних

Аналог: ngOnInit ≈ часто onMounted (или сразу в setup для sync-логики). ngOnDestroy ≈ onUnmounted.

7. Компонентная коммуникация

  • Parent → child: props (defineProps)
  • Child → parent: emits (defineEmits)
  • v-model на компоненте = prop + emit update
  • Дальние уровни: provide / inject (как DI «по дереву»)
  • Глобально: Pinia
  • Событийная шина в Vue 3 официально не рекомендуется (раньше был EventBus на Vue instance)

8. Pinia (стейт)

  • Stores: state, getters, actions
  • Можно Options-style или Setup-style store
  • Devtools, SSR-friendly, отличный TS
  • Проще NgRx: нет обязательных actions/reducers/effects для каждого чиха
NgRx → когда сложный поток событий. Pinia → когда нужен понятный shared state.

9. vue-router

  • History / hash mode
  • Nested routes, named views
  • Navigation guards: beforeEach, per-route beforeEnter, in-component guards
  • Lazy routes: () => import('./Page.vue')
  • Composition: useRouter(), useRoute()

10. Производительность и «фишки» Vue 3

  • Fragments — несколько корневых элементов в template
  • Teleport — рендер модалки в body
  • Suspense — async setup / async components (с оговорками)
  • Async components: defineAsyncComponent
  • Tree-shaking ядра — бандл меньше, чем «весь Vue 2»
  • KeepAlive — кэш динамических компонентов

11. Экосистема «сейчас»

  • Сборка: Vite
  • Meta: Nuxt 3 (SSR/SSG, file routing)
  • Тесты: Vitest + Vue Test Utils
  • UI: Vuetify, PrimeVue, Element Plus, Naive UI
  • Формы: VeeValidate / FormKit (часто)
Можно не учить в первую очередь. Это старое / legacy. На современном Vue 3 собесе достаточно знать «что было → чем заменили». Открывай только если в вакансии явно Vue 2 / Vuex / Options API.

Старые технологии (skip / только название)

Vue 2

Реактивность через Object.defineProperty — не ловила новые свойства без Vue.set, плохо с массивами/Map/Set. Один корневой элемент в template. Официально в EOL.

Сейчас: Vue 3 + Proxy, Fragments, Composition API.

Options API как «единственный стиль»

data(), methods, computed, watch, mixins. Всё ещё работает в Vue 3, но новый код пишут на Composition / script setup.

Сейчас: Composition API. Options — знать на чтение legacy.

Vuex

Старый официальный store: mutations (sync), actions (async), modules, namespaced. Много boilerplate.

Сейчас: Pinia (официальная замена).

Filters (| currency в template)

В Vue 2: {{ price | currency }}. В Vue 3 filters удалены.

Сейчас: methods / computed / обычные функции.

Mixins

Шарили логику, но ломали прозрачность: откуда взялось поле? Конфликты имён.

Сейчас: composables useXxx().

EventBus (new Vue() как шина)

Глобальные $on / $emit между кем угодно. Сложно отлаживать, утечки слушателей.

Сейчас: props/emits, provide/inject, Pinia. Или mitt — только если очень надо.

Vue CLI (webpack)

Старый стандартный scaffold на webpack.

Сейчас: Vite (+ create-vue / Nuxt).

Nuxt 2

На Vue 2, свой конфиг и модули эпохи webpack.

Сейчас: Nuxt 3 (Vue 3, Vite/Nitro).

$listeners, $scopedSlots, functional components (Vue 2 style)

API, которые сильно изменились или упростились в Vue 3.

Сейчас: slots / v-slot, обычные компоненты; смотри миграционный гайд только если трогаешь legacy.

AngularJS (Angular 1.x) — не путать

Это вообще другой фреймворк (ng-app, digest cycle). К Vue не относится, но иногда путают название «Angular».

Твой стек — Angular 2+ (TypeScript). AngularJS учить не нужно.

Шпаргалка Angular → Vue

@Input() → defineProps
@Output() → defineEmits
ngOnInit → onMounted
ngOnDestroy → onUnmounted
service + DI → composable / Pinia
async pipe + Observable → ref + async/await
*ngFor trackBy → :key в v-for
lazy routes → async components + vue-router

Топ Q&A (ответ в 1–2 предложения)

ref vs reactive?
ref — для примитивов и любого значения (доступ через .value). reactive — для объектов; удобнее деструктуризации через toRefs.
computed vs watch / watchEffect?
computed — производное значение с кэшем. watch — реакция на конкретный источник. watchEffect — сам трекает зависимости и сразу запускается.
v-if vs v-show?
v-if монтирует/удаляет из DOM. v-show только CSS display — лучше при частых переключениях.
Lifecycle: аналог ngOnInit / ngOnDestroy?
onMounted и onUnmounted (в Composition API). Также есть onBeforeMount, onUpdated и др.
Props / emits / v-model на компоненте?
Вход — defineProps, события — defineEmits. v-model на ребёнке = prop modelValue + emit update:modelValue (или именованный v-model).
Pinia?
Store: state, getters, actions. Проще и легче NgRx; нет лишней boilerplate-магии для типичных SPA.
Почему Vue 3 быстрее Vue 2?
Proxy вместо Object.defineProperty, лучше tree-shaking, Fragments, Teleport, более эффективный runtime compiler.
Как не дёргать UI лишний раз?
Правильные ключи в списках, computed вместо тяжёлой логики в template, при больших объектах — shallowRef / markRaw где нужно.
Scoped styles?
<style scoped> добавляет уникальные атрибуты — стили не текут наружу. Альтернатива — CSS modules.
SSR / Nuxt?
SSR рендерит HTML на сервере (SEO, первый paint). Nuxt — meta-фреймворк вокруг Vue: роутинг, SSR/SSG, conventions.

Как сказать про себя

Основной стек — Angular (~5 лет): DI, routing, change detection, RxJS. На Vue делал интерфейсы в телеком-проекте. Понимаю Composition API, реактивность Vue 3, SFC; готов быстро добрать Pinia/Router до прод-уровня — база TypeScript и SPA у меня уже есть.
